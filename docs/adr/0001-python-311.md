# ADR 0001 — Python 3.11 as the minimum version

**Status:** Accepted · 2026-08-13

## Context

DocMax v2 supported Python 3.9+. Raising the floor drops users on older
interpreters, so it needs to buy something concrete rather than being a
tidiness exercise.

## Decision

**Minimum supported version is Python 3.11.** CI tests 3.11, 3.12, and 3.13 on
Linux, macOS, and Windows.

Four features are load-bearing for this architecture, not incidental:

- **`tomllib`** (3.11). Config is TOML and parses with zero dependencies. v2
  used JSON with a hand-rolled loader that swallowed every exception and
  returned `{}` on a corrupt file — silently reverting every saved tool path.
- **`ExceptionGroup` / `except*`** (3.11). The batch runner reports N per-file
  failures as one structured group. v2 flattened errors into a list of
  `(path, str(exc))` tuples, losing the type of every failure and making
  "retry only the ones that timed out" impossible.
- **`StrEnum`** (3.11). Ghostscript presets, Pandoc formats, and OCR languages
  are enums, so an unvalidated user string can never reach an argv. v2
  interpolated `preset` straight into `-dPDFSETTINGS=/{preset}`.
- **`hashlib.file_digest()`** (3.11). Chunked file hashing for golden-test
  digests, the batch journal's resume key, and cloud idempotency keys — without
  hand-rolling a read loop for large files.

3.11 also brings a meaningful interpreter speedup and much better error
locations in tracebacks, which matters for a tool whose pitch includes "you
never see a traceback."

## Consequences

- Users on 3.9/3.10 stay on v2.x. Both reach end-of-life within the expected
  lifetime of v3, and 3.11 ships in every current distro and installer.
- `from __future__ import annotations` is still used everywhere for consistent
  runtime behaviour, not because the syntax requires it.
- The 3-OS × 3-version matrix is 9 cells. That is the cost of the badge meaning
  something.
